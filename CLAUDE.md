@AGENTS.md

Полное описание проекта — в `AGENTS.md`. Читать его целиком перед первой
правкой: почти вся логика здесь выведена из правил игры, и «упростить» её,
не зная этих правил, значит сломать данные.

## Четыре вещи, которые ломаются первыми

1. **Выработка кристаллов и тип узла — вычисляются, а не хранятся.** Не добавлять
   поля ввода: правила в `lib/crystals.ts` и `lib/map-rules.ts`, правка там
   пересчитывает все узлы без миграции.
2. **Роль проверяется в каждом мутирующем server action.** `useRole()` только
   прячет кнопки. Новый action без проверки роли — дыра. Карту и королевства
   правит админ, офицер ставит только статус узла.
3. **Королевств не «четыре», это таблица.** Перебирать только список из БД
   (`useKingdoms()` / `getKingdoms()`); `nodes.owner` хранит `kingdoms.id`, а не
   игровой номер. Статика карты зашита в `db/seed-data.ts` — правится через UI,
   потом `npm run db:export-seed`.
4. **Русский словарь в `lib/i18n.ts` — источник ключей.** Новый текст добавлять
   сразу в три языка, иначе не соберётся; в разметке только логические CSS-
   свойства (`ms-`, `ps-`, `start-`), иначе поедет арабский.
5. **Штаб (`/war-room`)** — карта только чтение по владению; тропы/чат/заметки
   — `plan_*` / `messages`, live через общий SSE. Новый mutator без `canPlan` /
   без `notify*` — дыра или «мёртвый» live. Деплой с `db:push` (таблицы штаба).

## Перед завершением работы

`npm run build` — он гоняет TypeScript и ловит и пропущенные переводы, и
рассинхрон схемы. Консоли дев-сервера не верить: она копит ошибки от
промежуточных компиляций, проверять на свежей вкладке.
